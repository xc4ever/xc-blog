# 场景草案v0.2：运输扰动下重卡电力服务的可兑现边界

日期：2026-10-25。阶段：候选问题收敛，尚未确认创新点或运行仿真。

后续进展：已运行固定任务的首个合成供电能力基准，见[结果与选题检查](2026-10-25-first-baseline-results.md)。正常上限500 kW，统一90分钟返回延误后上限200 kW；这只是明确假设下的确定性模型结果，未验证在线算法。新增文献也已覆盖备用边界、随机MPC与行程—电力服务联合安排，因此本文问题仍需细化，不能宣称空白。

## 一、为什么调整上一版

新增核读Bertucci、Salazar、Hofman的 *Battery Electric Truck Infrastructure Co-design via Joint Optimization and Agent-based Simulation*，IEEE TTE，2025，DOI：10.1109/TTE.2025.3575704。[大学接收稿](https://pure.tue.nl/ws/portalfiles/portal/359976260/TTE3575704_1_.pdf)。

模型已考虑载重相关能耗、辅助用电、装卸时间、可充电时段、桩数及接网功率，并以随机仿真验证。它说明上一版提出的“载重+接入窗口”应作为基础模型要求，不能独立认定为新贡献。本文核读模型与仿真段落，未复算结果。

新增Zackrisson等2026年[车队重新优化研究](https://www.nature.com/articles/s44333-026-00091-7)，也考虑载重相关耗电和装货位充电。运行方式与补能的协调已有较成熟研究。

因此把待研究问题改为“在实际运输约束和信息逐步到来的条件下，如何承诺并兑现电力服务”。这仍需继续检索服务承诺、备用、灵活性域等方向，不能以本轮阅读宣布空白。

## 二、一个可以具体讲清的运行故事

**假设场景，非真实案例复现**：工业园区同一运营方的10辆插枪充电牵引车，负责仓储点与生产节点之间的多趟短驳。园区已配置补能场站和固定储能，实际存在的反向供电设备则需要另行确认。

上午，运营方依据已知物流任务和车辆状态，判断下午某一时段可以提供多少电力服务。作出承诺后，一部分车辆受到装卸延误、临时任务或能耗偏差影响。运营方需要更新任务安排及充放电，决定继续履约、减少服务还是由其他资源补足。

**普通充电车辆分支**：服务指相对明确基线的充电负荷减少或转移，必须计入后续补能反弹。若基线本来不需要充电，不能凭空声称减少了负荷。

**明确具备双向功能的分支**：服务可以是指定场站/节点的净功率输出，需满足后续运输任务。与降低充电负荷分别计量。

**应急分支**：局部停电时，必要运输与已确定关键负荷争夺车辆和电量，使用有限时段的保供指标；不与正常市场收入直接混算。

生产与扩建并存可以产生不同优先级和到达时间的任务，但目前仍缺共享车队证据；不能预设两类任务必然混装或互换。

## 三、需要回答的三个问题

1. 静态汇总SOC与逐车任务排程，各自得到的服务能力相差多少，差异来自何处？
2. 任务、装卸和耗电发生变化时，原先承诺能否兑现；为降低违约风险需保留多少车辆和电量？
3. 增加固定储能、调整物流、降低服务承诺三种办法，哪种代价更小；移动能力本身何时有价值？

这些问题可被否定：若固定场站储能已完全覆盖服务，或运输强度使车队没有有意义的余量，应调整服务对象或转向补能保障，不为保留V2G强行制造场景。

## 四、第一版算例的边界

先采用固定短驳路线、可分配的任务和一个公共场站，验证运输与服务竞争关系。有真实多节点需求后再扩展配电拓扑和空间转运，避免把移动储能的价值与低价充电套利混淆。

运输任务最小字段：task_id、释放时刻、起终点、货量、允许车型、装卸时间、最晚到达、优先级。车辆字段：vehicle_id、位置、组合空车质量、容量、SOC、可充电功率。任务变化必须有到达时刻，不能让在线策略提前知道。

场站字段：node_id、接口数量、功率、场站接网余量、装卸与接入兼容性。服务字段：承诺时刻、服务节点、起止、要求功率、计量基线。若尚无市场规则，先研究功率请求，不把它称为已准入的交易产品。

最小状态流：等待/装卸 → 行驶 → 卸货/等待 → 返回/下一任务 → 可接入停车 → 补能或供电。仅“可接入停车”且分配到接口时允许能量交换；装卸并行接入要由场站属性显式允许。

## 五、公平对照与验收

| 方法 | 作用 |
| --- | --- |
| 静态余量估计 | 仅作能力误估参照，不能代替有竞争力的调度基准 |
| 确定性联合优化 | 用相同预测和已知任务安排运输、补能与服务 |
| MPC滚动优化 | 新信息到来后重排，作为主要在线基准候选 |
| 完全预知优化 | 仅作参考上界，明确提前知道未来 |
| 后续模型学习/MBRL | 需先发现可学习且影响决策的误差，并比较估计方法和MPC；不预设其胜出 |

各方法使用同样的期末SOC、任务优先级、设备、基线和可用信息；分别报告运输延误、SOC/容量违规、服务未兑现能量、兑现率、成本及求解时间。没有统计样本和明确风险口径前，不用“95%可靠”等措辞。

## 七、下一步优先顺序

1. 针对“重卡/商业车队+灵活性承诺/备用+随机物流任务”检索，确认此问题与既有服务调度研究的差异。
2. 用参数表筛选合理运输强度，先检验能量上限，不据此声称时空可行。
3. 建立明确标注的10辆车合成任务，运行确定性基准并检查可行性，再逐项引入扰动。
4. 补生产与扩建共用车队的证据；若没有，不阻塞基础场景研究，也不把它写成已证实的核心矛盾。
