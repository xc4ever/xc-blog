# 场景核验与首批数据清单

日期：2026-10-25。用途：把场景调查转成可与导师讨论、可执行的数据工作，不代表已经定题。

## 1. 目前应该推进什么

以“既有工业园区中10辆电动重卡的生产短驳与补能”为工作主场景；建设扩建作为待核实的任务变化来源。先回答：运输任务必须完成时，场站容量和车辆能量是否构成实际瓶颈，哪些时段还有可用灵活性？

将“分区检修期间临时供电”保留为待验证扩展。前一轮优先调查它，是因为事件窗口容易界定；目前尚未找到同一园区内货运任务、失电节点和重卡反向供电条件同时成立的证据，不能直接把它定为主要算例。

场景有价值不要求每个组成部分都首次出现。应先把真实约束和决策后果说清楚，再判断结果能否形成有用的新认识。单纯增加多网、节点或算法名称不能替代这一步。

## 4. 第一批数据：先取能跑通一天的最小集合

先取一个完整工作日作为数据联调，随后尽量覆盖连续一至两周及不同业务日。一天只能验证记录和模型是否一致，不能用于估计可靠的延误分布。

| 对象 | 最少字段 | 用途与核验 |
| --- | --- | --- |
| 车辆 | 匿名车辆编号、车型、电池标称/可用容量、SOC上下限 | 单位与容量口径一致；不直接把标称量当可用量 |
| 运输任务 | 任务编号、起讫点、计划及实际发到时间、货物类型、载重、期限 | 确认是否允许改派、提前、延后；识别共用车队 |
| 运行能耗 | 出发/到达SOC、里程、充电事件、可得时的电池累计电量 | 避免把途中补能计入行驶耗电；SOC分辨率单列 |
| 装卸停留 | 到场、装卸起止、排队、离场；是否可接电 | 直接检验“停车即能充电”的简化 |
| 补能设施 | 位置、端口数、单车及共享功率限制、实际记录 | 区分端口额定功率与站级总容量 |
| 场站用电 | 进口容量/运行限值、基础负荷时序、既有储能职责 | 计算可给车队的剩余容量，不能用变压器铭牌代替 |

如果增加反向供电，额外需要车辆与充电设备的双向兼容证明、可供功率、接口位置、并/离网运行方式以及接入管理条件。若增加临时保供，还需要负荷功率与持续时间、允许中断、失电范围和既有备用资源。暂态研究另需启动冲击、控制和保护参数。

只用匿名编号和必要运行字段；不要在研究数据里加入司机姓名、电话或客户身份。

## 5. 拿到资料后的判定顺序

1. **先复盘，不先优化。** 按实际任务和补能重放一天，核验SOC闭合及任务衔接；误差先排查时间戳、途中充电和容量口径。
2. **判断瓶颈。** 若现有方式无明显排队、容量或能量矛盾，不人为压低接网容量；转而检验经济性、服务边界，或换更有需求的业务日。
3. **建立最小公平基准。** 实际/先到先充策略、固定任务有序充电、允许范围内的任务与充电联合优化；相同任务、期末SOC及场站边界。
4. **再接电力服务。** 先报在不同运输要求下可提供多少功率和持续多久；待确认业务与设备条件后，再选具体市场产品或保供任务。
5. **再选算法。** 小规模确定性优化先作为参照。持续未知动态是否值得学习、滚动优化哪里失效，由实验判断；暂不承诺Model-based RL一定更合适。

下一阶段成功标准：得到一张可核查的“车辆—任务—补能—场站”日内记录；找出一个实际约束导致的可量化问题，或明确记录该候选未发现足够问题。两种结果都比扩大假设算例更有用。

## 6. 可向老师核实的五个问题

- 10辆车目前主要运什么、从哪里到哪里，是固定班次还是临时派单？
- 是否已有一个固定园区/企业可以获得匿名任务和补能记录？生产运输与建设物资是否确由同一批车承担？
- 车辆采用充电还是换电，具体车型是什么，是否已验证双向放电？
- 当前最明显的问题是排队、供电容量、能量不足、运输延误，还是电费？有没有具体一天可复盘？
- 园区是否确有检修/扩建临时供电需求，现有备用方案是什么；若没有，先从正常物流与补能开始是否符合课题安排？
