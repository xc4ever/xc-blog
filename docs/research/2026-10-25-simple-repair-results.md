# 简单补救规则：当前10组可行情形均不需要在线重优化保障期末能量

## 实现与公平边界

已运行`experiments/service-window/run_simple_repair.py`，输出`simple_repair_results.json`。读取上一轮扫描，在相同10组可行条件下比较；另外两组全天0/100kW原已被判不可行，未把它们算作规则失败或忽略为成功。

规则先用相同名义模型做一次整日优化，随后不再在线求解。因此它是“优化初始计划+简单执行补救”，不是完全不使用优化。

逐时保留当时可执行的原计划；车辆不在场或SOC空间不足导致的减充记为交流侧电量欠账。当前可接入车辆按欠账从大到小排序，在剩余接口、站级功率、单车功率和SOC空间内补齐。编号用于打破并列。未到公布时刻不读取延误，未来时段的动作不倒改；补救只偿还已欠电量，不猜测未来事件。

SOC空间与原离散模型一致，计入当时段已知辅助消耗；仍只检查半小时边界，不证明时段内连续动态可行。本文事件没有能耗误差，仅有等待延误，规则并未检验未知额外行驶耗电。

## 验证结果

- 10/10组达到期末最低SOC 0.8（数值容差内），无未偿还的实质电量欠账。
- 实际可接入时间、单车功率、接口数、站级容量与请求窗口上限均通过检查；SOC上下界无实质违规。
- 逐车整日能量守恒最大残差约8.53×10⁻¹⁴kWh。
- 延误30/90分钟配对案例，在14:00消息公布前充电动作最大差异0kW。
- 全天总充电均约2042.105kWh，与滚动方法一致。

## 与滚动方法的区别

| --- | ---: | ---: | ---: |
| 14—16 | 0 | 530.526 | 530.526 |
| 14—16 | 100 | 393.684 | 330.526 |
| 14—16 | 300/600 | 317.895 | 316.842 |
| 12—18 | 0 | 909.474 | 909.474 |
| 12—18 | 100 | 404.211 | 354.211 |
| 12—18 | 300/600 | 178.526 | 178.526 |
| 6—22 | 300/600 | 无窗口后时段 | 无窗口后时段 |

部分条件下滚动方法更早补能，但本轮目标只是合成的尽早充电偏好。没有实际分时价格、峰值计费或下一日任务，不把这些时序差异称为已证实的经济收益；更早补能也不自动意味着对电网更有价值。

上一轮固定计划在部分情形下缺少60kWh期末电量，其原因是取消充电后完全没有补救。本轮表明简单规则即可修复，不能再以该缺口证明在线MILP或RL必要。

## 对研究主线的决定

保留这个简单规则作为后续主要基准之一。不为制造算法优势随意增加任务或缩减设备。

当前可支持的研究工作是：检查真实任务下可提供什么灵活性，以及需要付出多少后续补能与资源占用。尚不支持承诺“提出复杂算法即可显著改善”。后续有实际能耗偏差、任务变化、临时供电要求时，先核查这个规则为何失败，再判断是否需要滚动联合优化或模型学习。

一个事件、十组人为窗口远不足以证明规则普遍有效。下一阶段应将现有结果整理成导师可讨论的场景与待核实问题，而不是继续只凭合成参数扩大算例。
